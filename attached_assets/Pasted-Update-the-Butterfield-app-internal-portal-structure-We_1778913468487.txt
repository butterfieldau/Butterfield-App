Update the Butterfield app internal portal structure.

We are removing the separate Staff Portal and Manager Portal completely from the app and server.

Use the existing Director Portal as the base and rebuild it into one unified Internal Portal for all internal users.

The only internal roles should be:

1. Master
2. Director
3. Store Manager
4. Staff

Do not create any other internal roles.

Important:
- Master controls absolutely everything.
- Director has full business/admin access, but cannot override Master-level controls.
- Store Manager has store-level operational access.
- Staff has basic shift/staff access only.

Everyone must clock in and clock out except:
- Master
- Director

Store Manager and Staff must always clock in/out.

Remove completely:
- Old Staff Portal routes
- Old Staff Portal pages
- Old Staff Portal components
- Old Staff Portal API endpoints if they are duplicated or unsafe
- Old Manager Portal routes
- Old Manager Portal pages
- Old Manager Portal components
- Old Manager Portal API endpoints if they are duplicated or unsafe
- Any old portal navigation that points to Staff Portal or Manager Portal

Do not leave hidden, unused or accessible routes on the server.

Create one portal only:

Internal Portal

This Internal Portal should use the existing Director Portal UI, layout, dashboard, styling and structure as the base, then adjust the navigation and permissions based on the logged-in user role.

Role permissions:

- All Staff

- Security logs
- Push notifications
- Promo codes
- Wholesale pricing tiers
- Wholesale customers
- Customer accounts
- System settings
- API settings
- Integrations
- Database management tools if available

Master can:
- Create, edit and delete Director accounts
- Create, edit and delete Store Manager accounts
- Create, edit and delete Staff accounts
- Change permissions for every role
- Override user permissions
- Assign users to stores
- Disable or enable accounts
- View and manage all portal data
- Access every internal feature without restriction

Master does not clock in/out.

Director can access:

STORE MANAGER ROLE

Store Manager must only access the stores they are assigned to.

Store Manager can access:
- Assigned store dashboard

- Assigned store rosters
- Assigned store product availability

- Assigned store wholesale order notes if the order is linked to their store
- Staff announcements

Store Manager can:
- View assigned staff

- Manage daily tasks
- Update stock availability
- Update order status
- Add daily notes
- View operational reports for their store
- Approve basic shift-related requests if this feature exists
- Handle customer order issues for assigned store

Store Manager cannot:
- Access other stores unless assigned
- Create Director accounts
- Create Master accounts
- Change role permissions
- Access full financial reports
- Access global app settings
- Access system settings
- Access API settings
- Delete users

- Delete wholesale accounts

- Edit QR reward logic

- View payroll exports unless specifically allowed by Director or Master

Store Manager must clock in/out.

CLOCK IN / CLOCK OUT RULES

Add or confirm the setting:

requires_clock_in

Default:
- Master: false
- Director: false
- Store Manager: true
- Staff: true

The clock in/out system must be linked to:
- User role
- Assigned store
- Shift/roster if available
- Payroll export
- Staff reports
- Store Manager dashboard
- Director dashboard
- Master dashboard

Make sure Store Managers and Staff cannot bypass clock in/out requirements.

PORTAL STRUCTURE

Final portal structure should be:

1. Customer Portal
2. Wholesale Portal
3. Internal Portal

The Internal Portal replaces:
- Director Portal
- Manager Portal
- Staff Portal

The Internal Portal should be based on the existing Director Portal.

After login:
- Detect the user role
- Send internal users to the Internal Portal
- Show/hide navigation based on role permissions
- Block all restricted pages on the backend
- Block all restricted API requests on the backend
- Do not only hide frontend buttons

SECURITY REQUIREMENTS

Permissions must be enforced at:
- Frontend navigation level
- Page route level
- Backend/API level
- Database query level where needed

If a Staff user or Store Manager manually types a restricted URL, the app must block access.

If a Staff user or Store Manager tries to call a restricted API endpoint, the backend must reject the request.

Add audit logging for sensitive actions including:
- Creating users
- Editing users
- Disabling users
- Changing roles
- Changing permissions
- Product price changes
- Product deletion
- Wholesale pricing changes
- Loyalty changes
- QR reward changes
- Refunds
- Order cancellations
- Payroll exports
- App settings changes

The Internal Portal must stay linked with customer data including:
- Customer accounts
- Customer orders
- Customer order history

- Coffee reward QR codes

- Customer rewards

- Wholesale invoices/order notes if available
