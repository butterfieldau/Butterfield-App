Upgrade the Butterfield app product system so the coffee menu, cookies, drinks and future products are built properly with categories, variants, add-ons and synced cleanly across the customer app, staff portal, wholesale portal and director backend.

Do not rebuild the whole app. Upgrade the existing product, ordering, cart, loyalty and backend structure without breaking the current portals, users, customers, orders, staff, wholesale accounts or product data.

10. Loyalty Points

Fix and improve the loyalty points system.

When a customer completes an order:
- Points should be added only after the order is paid and confirmed
- Points should be based on the final paid amount
- Points should not be added for cancelled, failed, refunded or unpaid orders

If an order is cancelled:
- Any points earned from that order must be removed from the customer account

If an order is refunded:
- Points must be removed based on the refunded amount
- Full refund removes all points from that order
- Partial refund removes the correct portion of points

Create a loyalty points transaction history.

Each points transaction should include:
- Customer ID
- Order ID
- Points added
- Points removed
- Reason
- Date
- Status
- Created by system/director

Example reasons:
- Order completed
- Order cancelled
- Full refund
- Partial refund
- Manual adjustment
- Director correction

Do not allow duplicate points to be added if the order status changes multiple times.

11. Backend Sync

Everything must stay synced properly.

When a director edits a product, variant, category, price or option:
- Public app should update
- Staff portal should update
- Wholesale portal should update if applicable
- Cart should use the latest pricing
- Old orders should keep their historical price and selected options
- New orders should use the updated price and options

Do not let product edits break old order records.
