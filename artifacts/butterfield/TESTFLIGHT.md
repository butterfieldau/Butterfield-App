# Butterfield TestFlight / EAS Build Guide

This Expo app is configured for iOS App Store/TestFlight builds through EAS.

## Prerequisites

- Expo account access.
- Apple Developer Program membership.
- An App Store Connect app using bundle ID `au.com.butterfieldcookies.app`.
- App Store Connect access that can create signing credentials and upload builds.

---

## Build Profiles

There are two production build profiles in `eas.json`:

| Profile | `IS_POS_BUILD` | Star IO / TCP | Use case |
|---------|----------------|---------------|----------|
| `production` | `0` | **Excluded** (pods + Metro stubs) | Consumer App Store binary |
| `production-pos` | `1` | **Included** (fully linked) | In-store POS hardware |

---

## Consumer Build (App Store / TestFlight)

```sh
# From the repository root:
pnpm --filter @workspace/butterfield run ios:build:testflight
```

Or via EAS directly:
```sh
eas build --profile production --platform ios
```

- StarIO10 and react-native-tcp-socket are excluded at three independent layers:
  1. `react-native.config.js` — RN CLI sets `ios: null` so autolinking skips them
  2. `plugins/withPodfileExclusion.js` — CocoaPods `pre_install` hook rejects those specs before they are compiled or linked
  3. `metro.config.js` — bundler resolves to safe no-op stubs (`stubs/star-io10-stub.js`, `stubs/tcp-socket-stub.js`)
- The ObjC shim (`plugins/withStarIOLazyInit.js`) is always injected but is a safe no-op when StarIO10 is absent (`NSClassFromString` returns `nil`).
- Star TCP printing and Epson TCP printing both work via raw bytes over port 9100 — only the Star *native SDK* drawer path is unavailable.

### Submit to TestFlight

```sh
pnpm --filter @workspace/butterfield run ios:submit:testflight
# or:
eas submit --profile production --platform ios
```

## POS Build (In-Store Hardware)

```sh
eas build --profile production-pos --platform ios
```

- Both StarIO10 and react-native-tcp-socket are **kept** — the pod exclusion hook and Metro stubs are both bypassed when `IS_POS_BUILD=1`.
- The ObjC shim (`StarIOSafeInit.m`, generated by `plugins/withStarIOLazyInit.js`) is compiled into the binary to guard against iOS 26 / arm64e startup crashes caused by the Star SDK's TurboModule eager-init.
- The JS `loadStarSdk()` helper in `lib/printer.ts` uses `new Function('return import("react-native-star-io10")')()` so Metro's static analyser does not follow the import path (prevents accidental stub replacement at bundle time).

### POS Build Verification Checklist

After triggering an EAS `production-pos` build, run these checks before shipping to staff:

#### 1 — Pod linkage (build server)

In the EAS build log, confirm the CocoaPods install step lists:
```
Installing react-native-star-io10 x.y.z
Installing StarIO10 x.y.z
Installing react-native-tcp-socket x.y.z
```

The `pre_install` rejection log line (`Consumer build: remove POS-only pods`) must **not** appear.

#### 2 — ObjC shim compile (build server / Xcode)

In the Xcode compile log (accessible via EAS build artefacts or a local `expo prebuild` + `xcodebuild`):
- `StarIOSafeInit.m` should compile without warnings at `-Wall -Wextra`.
- Expected: `[StarIOSafeInit] StarIO10 init swizzled for iOS 26 safety (full method no-op on failure).` in the device console at app launch.
- Acceptable on a healthy Star printer: the swizzled `-init` succeeds and the shim is dormant.

#### 3 — Test print (real device, Director → Settings → Printer)

1. Open the Director portal → tap the store → scroll to Printer Settings.
2. Enter the Star printer's local IP.
3. Set **Printer Brand** to **Star**.
4. Tap **Send Test Print** → receipt should emerge from the printer.
5. Enable **Auto-open Cash Drawer**.
6. Tap **Test Open Drawer** → drawer should spring open.
   - This calls `sendOpenDrawer(..., printerBrand)` which routes to `tryOpenDrawerWithStarSdk`.
   - A success toast ("Cash drawer opened successfully.") confirms the Star SDK path ran end-to-end.
   - Any failure here indicates the Star SDK is not linked or the drawer is not connected to the printer.

#### 4 — Linkmap check (optional, deeper verification)

In the `.ipa` artefact:
```sh
# Unzip the .ipa and inspect the binary:
nm Payload/Butterfield.app/Butterfield | grep -i starprinter
```
Should return several Star SDK symbols confirming the framework is linked.

## Static Verification Summary (June 2026)

All four layers of the POS build have been statically verified to be correct:

| Layer | IS_POS_BUILD=0 behaviour | IS_POS_BUILD=1 behaviour | Verified |
|-------|--------------------------|--------------------------|----------|
| `react-native.config.js` | `ios: null` for both modules | No exclusion; normal autolinking | ✓ |
| `plugins/withPodfileExclusion.js` | Injects `pre_install` hook | Returns config unchanged | ✓ |
| `metro.config.js` | Resolves to stubs | Resolves to real modules | ✓ |
| `plugins/withStarIOLazyInit.js` | Shim is no-op (`NSClassFromString` → nil) | Shim swizzles `-init` for iOS 26 safety | ✓ |

**Bug fixed (June 2026):** `app/(director)/stores.tsx` "Test Open Drawer" button was calling `sendOpenDrawer(ip, port, undefined, drawerPin)` without passing `printerBrand`. This meant the Star SDK path (`tryOpenDrawerWithStarSdk`) was never triggered even with Brand set to Star. Fixed: `printerBrand` is now passed as the 5th argument.

**ObjC shim Xcode 16 review:** `imp_implementationWithBlock`, `class_copyMethodList` (with `free()`), `method_setImplementation`, and the `NSException @try/@catch` block have no known warnings on Xcode 16 / iOS 26 SDK. The block captures `originalIMP` and `universalNoopIMP` by value (both are C pointer types; no ARC retain cycle). `NSClassFromString` guard makes the shim a safe no-op in consumer builds.

**TypeScript typecheck:** passes cleanly after the `stores.tsx` fix.

## Notes

- The first TestFlight upload must match the App Store Connect bundle ID.
- If the App Store Connect record uses a different bundle ID, update `ios.bundleIdentifier` in `app.json` before building.
- Incrementing iOS build numbers is handled automatically by `autoIncrement: true` in both production profiles.
- When Star Micronics ships a new SDK version, verify the iOS 26 crash is still suppressed before bumping the version pin in `package.json`. Update the "Validated against" line in `plugins/withStarIOLazyInit.js`.
